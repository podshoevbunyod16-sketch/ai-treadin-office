# AI Trading Office

Торговый офис для **MetaTrader 5**: подключение брокерских счетов, котировки и графики в реальном времени,
ручная торговля (рыночные и отложенные ордера, SL/TP, частичное закрытие), позиции, баланс, история сделок,
торговые боты с отдельной средой исполнения, мониторинг, журнал аудита, роли пользователей.

* **Backend** — Python 3.11, FastAPI, SQLAlchemy (SQLite или PostgreSQL), WebSocket, JWT, bcrypt, Fernet.
* **Frontend** — React 19 + TypeScript + Vite, графики TradingView `lightweight-charts`.
* **MT5** — официальный Python-пакет MetaQuotes [`MetaTrader5`](https://pypi.org/project/MetaTrader5/).

## ⚠️ Статус проверки (важно)

| Что | Статус |
|---|---|
| Backend, API, WebSocket, БД, безопасность, боты, UI | Реализованы, покрыты автотестами (56 backend + 10 frontend), production-сборка проходит |
| Код интеграции с MT5 (`app/mt5/client.py`) | Написан по официальному API `MetaTrader5` (функции, константы, коды возврата) |
| **Проверка на реальном MT5-демосчёте** | **Не выполнена** — см. причины ниже |

**Почему не было проверки на реальном демосчёте:**

1. Официальный пакет `MetaTrader5` выпускается **только под Windows x64** (на PyPI есть только колёса `win_amd64`) и
   общается с **запущенным терминалом MetaTrader 5** через IPC. Среда разработки — Linux-контейнер без Windows
   и без терминала, поэтому `pip install MetaTrader5` там невозможен.
2. Из среды разработки закрыт исходящий доступ в интернет (кроме GitHub, npm, PyPI), поэтому подключиться
   к торговому серверу брокера было бы невозможно даже через удалённый терминал.
3. Учётные данные демосчёта не передавались.

Поэтому интеграционные тесты MT5 выполняются на **тестовом двойнике API MetaTrader5**
(`backend/tests/mt5_testkit/`). Он есть **только в тестах**: в продукт он не попадает, демо-режимов
и фейковых котировок в приложении нет. Если MT5 недоступен, интерфейс и API прямо сообщают причину
(например: «Python-пакет MetaTrader5 не установлен… выпускается только для Windows x64…»).

**Как проверить на своём демосчёте** (≈10 минут): раздел [«Быстрый старт с реальным MT5»](#быстрый-старт-с-реальным-mt5).

## Архитектура

```
 Браузер ──HTTP/WS──►  Backend (FastAPI)  ──┬── local:  отдельный процесс-воркер на каждый счёт ──► MetaTrader5 ──► терминал MT5
  (React UI)            • REST API /api     │           (backend на Windows рядом с терминалом)
                        • WebSocket /ws     │
                        • AccountManager    └── bridge: HTTPS + токен ──► MT5-мост (Windows/VPS) ──► MetaTrader5 ──► терминал MT5
                        • BotManager                    python -m app.mt5.bridge_server
                        • SQLite/PostgreSQL
```

* **Два типа подключения счёта**
  * `bridge` (рекомендуется) — backend работает где угодно (Linux, Docker, облако), а рядом с терминалом
    на Windows запускается лёгкий агент `app.mt5.bridge_server`. Один мост = один терминал = один счёт.
    Доступ по Bearer-токену (сравнение за константное время), опционально TLS.
  * `local` — backend запущен на Windows. Для каждого счёта создаётся **отдельный процесс** (пакет MetaTrader5 —
    синглтон на процесс), падение/зависание одного счёта не влияет на остальные; таймаут вызова убивает воркер.
* **AccountManager** — подключение/отключение, автоподключение при старте, watchdog-переподключение
  при обрыве, стриминг котировок (по умолчанию 1 с) и снимков счёта/позиций/ордеров (2 с) в WebSocket.
* **Боты** — каждый бот выполняется в своей изолированной задаче со своим состоянием (сохраняется в БД
  и переживает перезапуск), журналом, риск-лимитами и **уникальным magic-номером**: по нему его ордера,
  позиции и сделки отделяются в MT5 от других ботов и ручной торговли. Исключения внутри бота не влияют
  на остальные; после 10 ошибок подряд бот останавливается со статусом `error`. Боты, которые работали
  до перезапуска сервера, запускаются снова и ждут подключения счёта.

### Стратегии

| Ключ | Описание |
|---|---|
| `sma_cross` | Пересечение быстрой и медленной SMA/EMA |
| `rsi_reversion` | Возврат к среднему по RSI (Wilder), выход у уровня 50 |
| `donchian_breakout` | Пробой канала Дончиана, выход по короткому каналу |
| `ml_logistic` | **AI**: логистическая регрессия, переобучается на каждом новом баре по истории MT5 (лаги доходности, RSI, отклонение от SMA в ATR). Торгует, только если точность на отложенной выборке выше порога |

Все стратегии считают сигналы **только по закрытым барам** из `copy_rates_from_pos`, один раз на бар.
Режимы бота: «Торговля» (ордера в MT5) или «Только сигналы» (сигналы пишутся в журнал, ордера не отправляются).

### Риск-менеджмент бота
объём, SL/TP в пунктах (цены считаются от фактической котировки исполнения), макс. число позиций,
макс. спред, дневной лимит убытка (реализованный P/L по истории сделок MT5 + плавающий), торговые часы (UTC),
допустимое проскальзывание, закрытие позиций при остановке. Плюс глобальная кнопка **«Стоп всех ботов»**.

### Безопасность
* JWT (HS256) с версионированием токена: смена пароля/роли/блокировка мгновенно отзывает сессии.
* Пароли — bcrypt (12 раундов), политика сложности; защита от перебора (10 неудачных попыток за 5 мин → 429).
* Пароли счетов и токены мостов хранятся в БД **зашифрованными** (Fernet/AES), в API никогда не возвращаются.
* Роли: `admin` (всё + пользователи + удаление счетов), `trader` (торговля, счета, боты), `viewer` (только просмотр).
* **Торговля на реальных счетах запрещена по умолчанию** (`ATO_ALLOW_REAL_TRADING=false`): тип счёта берётся
  из `account_info().trade_mode`, на `real` все торговые операции (ручные и ботов) отклоняются.
* Журнал аудита всех торговых и административных действий (с IP), заголовки безопасности, валидация ввода.

## Быстрый старт

Требования: Python 3.10+, Node.js 20+.

```bash
./scripts/run.sh            # собирает frontend и запускает сервер на http://0.0.0.0:8000
```

Откройте `http://localhost:8000` — при первом входе будет предложено создать администратора.
Документация API: `http://localhost:8000/api/docs`.

Разработка с hot-reload:
```bash
cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
cd frontend && npm install && npm run dev      # http://localhost:5173, /api и /ws проксируются на :8000
```

Настройки — переменные окружения `ATO_*` (см. `backend/.env.example`).

## Быстрый старт с реальным MT5

1. На Windows-ПК/VPS установите MetaTrader 5, откройте демосчёт у брокера (например, MetaQuotes-Demo) и
   включите **Сервис → Настройки → Советники → Разрешить алгоритмическую торговлю**.
2. Скопируйте репозиторий и запустите мост (PowerShell):
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\start_bridge.ps1 -Port 8765
   ```
   Скрипт установит зависимости (включая `MetaTrader5`), сгенерирует и покажет `ATO_BRIDGE_TOKEN`.
   Для доступа через интернет используйте VPN/SSH-туннель или TLS (`-CertFile cert.pem -KeyFile key.pem`)
   и откройте порт только для IP сервера офиса.
3. В веб-интерфейсе: **Счета MT5 → Добавить счёт** → тип «MT5-мост», логин, сервер, пароль (или пусто,
   если терминал уже авторизован под этим счётом), URL моста `http(s)://<ip>:8765` и токен → **Подключить**.
4. **Терминал**: добавьте символы в «Обзор рынка», проверьте котировки/график, откройте и закройте
   позицию 0.01 лота. **Боты**: создайте бота, запустите, наблюдайте журнал и мониторинг.

Если backend тоже работает на этой Windows-машине, можно выбрать тип «Локально» (мост не нужен).

## Известные ограничения
* Время в данных MT5 (бары, сделки) — время торгового сервера брокера; отображается как есть.
  Дневной лимит убытка считается от полуночи UTC.
* Один мост обслуживает один терминал; для N счетов нужно N терминалов (у каждого своя папка) и N мостов.
* Схема БД создаётся автоматически при старте (`create_all`); для изменения схемы в будущих версиях
  потребуются миграции.
