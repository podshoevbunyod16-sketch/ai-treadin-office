# AI Trading Office

Торговый офис для **MetaTrader 5**: подключение брокерских счетов, котировки и графики в реальном времени,
ручная торговля (рыночные и отложенные ордера, SL/TP, частичное закрытие), позиции, баланс, история сделок,
торговые боты с отдельной средой исполнения, мониторинг, журнал аудита, роли пользователей.

* **Backend** — Python 3.11, FastAPI, SQLAlchemy (SQLite или PostgreSQL), WebSocket, JWT, bcrypt, Fernet.
* **Frontend** — React 19 + TypeScript + Vite, графики TradingView `lightweight-charts`.
* **MT5** — напрямую через официальный Python-пакет MetaQuotes [`MetaTrader5`](https://pypi.org/project/MetaTrader5/)
  (`import MetaTrader5 as mt5`): сервер приложения запускается на Windows рядом с терминалом.

**Запуск на Windows:** установите MetaTrader 5, войдите в демосчёт, включите «Алго-трейдинг» и запустите
`start.bat` → откроется `http://127.0.0.1:8000`. Подробно — [«Быстрый старт (Windows + MetaTrader 5)»](#быстрый-старт-windows--metatrader-5).

## ⚠️ Статус проверки (важно)

| Что | Статус |
|---|---|
| Backend, API, WebSocket, БД, безопасность, боты, UI | Реализованы, покрыты автотестами (80 backend + 10 frontend), production-сборка проходит |
| Код интеграции с MT5 (`app/mt5/client.py`) | Написан по официальному API `MetaTrader5` (функции, константы, коды возврата, `last_error`) |
| Проверка на вашей машине | `scripts\check_mt5.bat --trade` — тем же кодом подключается к терминалу, читает данные, делает тестовую сделку 0.01 на DEMO |
| **Проверка на реальном MT5-демосчёте** | **Не выполнена** — см. причины ниже |

**Почему не было проверки на реальном демосчёте:**

1. Официальный пакет `MetaTrader5` выпускается **только под Windows x64** (на PyPI есть только колёса `win_amd64`) и
   общается с **запущенным терминалом MetaTrader 5** через IPC. Среда разработки — Linux-контейнер без Windows
   и без терминала, поэтому `pip install MetaTrader5` там невозможен.
2. Из среды разработки закрыт исходящий доступ в интернет (кроме GitHub, npm, PyPI), поэтому подключиться
   к торговому серверу брокера было бы невозможно даже через удалённый терминал.
3. Учётные данные демосчёта не передавались.

Поэтому интеграционные тесты MT5 выполняются на **тестовом двойнике API MetaTrader5**
(`backend/tests/mt5_testkit/`). Он есть **только в тестах**: в продукт он не попадает, демо-режимов
и фейковых котировок в приложении нет. Если MT5 недоступен, интерфейс и API прямо сообщают причину
(например: «Python-пакет MetaTrader5 не установлен… выпускается только для Windows x64…»).

**Как проверить на своём демосчёте** (≈10 минут): раздел [«Быстрый старт (Windows + MetaTrader 5)»](#быстрый-старт-windows--metatrader-5).

## Архитектура

```
 Браузер ──HTTP/WS──►  Backend (FastAPI)  ──┬── local:  отдельный процесс-воркер на каждый счёт ──► MetaTrader5 ──► терминал MT5
  (React UI)            • REST API /api     │           (backend на Windows рядом с терминалом)
                        • WebSocket /ws     │
                        • AccountManager    └── bridge: HTTPS + токен ──► MT5-мост (Windows/VPS) ──► MetaTrader5 ──► терминал MT5
                        • BotManager                    python -m app.mt5.bridge_server
                        • SQLite/PostgreSQL
```

* **Два типа подключения счёта**
  * `local` (**основной, по умолчанию**) — backend запущен на Windows рядом с терминалом и работает с ним напрямую
    через `import MetaTrader5 as mt5`. Для каждого счёта создаётся **отдельный процесс** (пакет MetaTrader5 —
    синглтон на процесс, один процесс = один терминал), падение/зависание одного счёта не влияет на остальные;
    таймаут вызова убивает воркер, watchdog переподключает.
  * `bridge` (опционально) — если backend должен работать не на Windows (Linux, Docker, облако): рядом с терминалом
    запускается агент `app.mt5.bridge_server` с тем же `MT5Client`. Доступ по Bearer-токену, опционально TLS.
* **AccountManager** — подключение/отключение, автоподключение при старте, watchdog-переподключение
  при обрыве, стриминг котировок (по умолчанию 1 с) и снимков счёта/позиций/ордеров (2 с) в WebSocket.
* **Боты** — каждый бот выполняется в своей изолированной задаче со своим состоянием (сохраняется в БД
  и переживает перезапуск), журналом, риск-лимитами и **уникальным magic-номером**: по нему его ордера,
  позиции и сделки отделяются в MT5 от других ботов и ручной торговли. Исключения внутри бота не влияют
  на остальные; после 10 ошибок подряд бот останавливается со статусом `error`. Боты, которые работали
  до перезапуска сервера, запускаются снова и ждут подключения счёта.

### Что делает слой MT5 (`app/mt5/client.py`) поверх «сырого» API
* `initialize()` с логином/паролем/сервером или подключение к уже авторизованному терминалу; повтор при IPC-таймауте
  (терминал ещё запускается); понятные подсказки по кодам `last_error` (-10003 терминал не найден, -6 авторизация…).
* **Проверки перед сделкой**: кнопка «Алго-трейдинг» (`terminal_info().trade_allowed`), запрет Python API
  (`tradeapi_disabled`), вход по инвесторскому паролю (`account_info().trade_allowed`), запрет советников брокером
  (`trade_expert`), режим торговли символом (`SYMBOL_TRADE_MODE_DISABLED/LONGONLY/SHORTONLY/CLOSEONLY`).
* Нормализация объёма (min/max/step/`volume_limit`) и цен к `trade_tick_size`; проверка SL/TP относительно
  `trade_stops_level` (по Bid для BUY, по Ask для SELL) и стороны цены отложенного ордера — до отправки, с понятной ошибкой.
* Автовыбор режима заполнения (FOK/IOC/RETURN) с фолбэком при 10030; **повтор с новой котировкой** при реквоте
  (10004), смене цены (10020) и отсутствии цен (10021) — до 3 попыток; закрытие позиции противоположной сделкой
  с `position=ticket` (хеджинг и неттинг).
* `order_check` (проверка маржи), `order_calc_margin` / `order_calc_profit` (маржа, P/L при SL/TP, стоимость пункта —
  показывается в тикете ордера), `market_book_*` (стакан), `copy_rates_from_pos` с повтором (история подгружается).
* Определение смещения времени торгового сервера от UTC (все времена MT5 — серверные); дневной лимит убытка бота
  считается от начала торгового дня сервера.
* **Диагностика** счёта (кнопка «Диагностика» в разделе «Счета MT5» и CLI `python -m app.mt5.diagnose`): связь
  с сервером, «Алго-трейдинг», Python API, права счёта, тип счёта, хеджинг/неттинг, пинг, время сервера.

### Стратегии

| Ключ | Описание |
|---|---|
| `sma_cross` | Пересечение быстрой и медленной SMA/EMA |
| `rsi_reversion` | Возврат к среднему по RSI (Wilder), выход у уровня 50 |
| `donchian_breakout` | Пробой канала Дончиана, выход по короткому каналу |
| `ml_logistic` | **AI**: логистическая регрессия, переобучается на каждом новом баре по истории MT5 (лаги доходности, RSI, отклонение от SMA в ATR). Торгует, только если точность на отложенной выборке выше порога |

Все стратегии считают сигналы **только по закрытым барам** из `copy_rates_from_pos`, один раз на бар.
Режимы бота: «Торговля» (ордера в MT5) или «Только сигналы» (сигналы пишутся в журнал, ордера не отправляются).

### Риск-менеджмент бота
объём, SL/TP в пунктах (цены считаются от фактической котировки исполнения), макс. число позиций,
макс. спред, дневной лимит убытка (реализованный P/L по истории сделок MT5 за торговый день сервера + плавающий), торговые часы (UTC),
допустимое проскальзывание, закрытие позиций при остановке. Плюс глобальная кнопка **«Стоп всех ботов»**.

### Безопасность
* JWT (HS256) с версионированием токена: смена пароля/роли/блокировка мгновенно отзывает сессии.
* Пароли — bcrypt (12 раундов), политика сложности; защита от перебора (10 неудачных попыток за 5 мин → 429).
* Пароли счетов и токены мостов хранятся в БД **зашифрованными** (Fernet/AES), в API никогда не возвращаются.
* Роли: `admin` (всё + пользователи + удаление счетов), `trader` (торговля, счета, боты), `viewer` (только просмотр).
* **Торговля на реальных счетах запрещена по умолчанию** (`ATO_ALLOW_REAL_TRADING=false`): тип счёта берётся
  из `account_info().trade_mode`, на `real` все торговые операции (ручные и ботов) отклоняются.
* Журнал аудита всех торговых и административных действий (с IP), заголовки безопасности, валидация ввода.

## Быстрый старт (Windows + MetaTrader 5)

Требования: Windows 10/11 x64, **64-битный** Python 3.10+ ([python.org](https://www.python.org/downloads/windows/),
галочка «Add to PATH»), терминал MetaTrader 5. Node.js LTS нужен только если папки `frontend/dist` нет
(`start.bat` сам соберёт интерфейс).

1. Установите MetaTrader 5, откройте **демосчёт** (например, MetaQuotes-Demo или у своего брокера) и войдите в него.
2. Включите кнопку **«Алго-трейдинг»** на панели терминала. В *Сервис → Настройки → Советники* не должна стоять
   галочка запрета торговли через внешний Python API.
3. Дважды щёлкните **`start.bat`** в корне проекта. Скрипт проверит Python (64 бит), создаст `backend\.venv`,
   установит зависимости **включая `MetaTrader5`**, при необходимости соберёт интерфейс и запустит сервер
   на `http://127.0.0.1:8000` (параметры: `start.bat -BindHost 0.0.0.0 -Port 8000 -Rebuild`).
4. В браузере создайте администратора → **Счета MT5 → Добавить счёт**: тип «Напрямую: библиотека MetaTrader5»,
   логин, сервер (точно как в окне входа MT5), пароль (можно оставить пустым, если терминал уже авторизован
   под этим счётом) → **Подключить** → **Диагностика** (все пункты должны быть зелёными).
5. **Терминал**: добавьте символы, проверьте котировки/график/стакан, посмотрите расчёт маржи и P/L при SL/TP,
   откройте и закройте позицию 0.01 лота. **Боты**: создайте бота, запустите, наблюдайте журнал и мониторинг.

### Проверка интеграции из командной строки

```bat
rem подключиться к уже авторизованному терминалу и проверить всё
scripts\check_mt5.bat
rem + открыть и закрыть позицию минимальным лотом (только DEMO)
scripts\check_mt5.bat --trade
rem указать счёт явно (пароль будет запрошен) и символ
scripts\check_mt5.bat --login 5012345 --server MetaQuotes-Demo --symbol EURUSD
rem если установлено несколько терминалов
scripts\check_mt5.bat --path "C:\Program Files\MetaTrader 5\terminal64.exe"
```
Это `python -m app.mt5.diagnose` — тот же `MT5Client`, что и в веб-приложении. Вывод — список `[OK]/[WARN]/[FAIL]`
(версия терминала, счёт, настройки, котировка, бары, маржа, `order_check`, позиции, история, тестовая сделка).

### Несколько счетов
Пакет `MetaTrader5` подключается к одному терминалу на процесс; приложение запускает отдельный процесс на каждый
счёт, но **каждому счёту нужен свой установленный терминал** (отдельная папка установки) — укажите путь
к его `terminal64.exe` в настройках счёта.

### Сервер приложения не на Windows (опционально)
На Windows-машине с терминалом запустите мост
`powershell -ExecutionPolicy Bypass -File scripts\start_bridge.ps1 -Port 8765` (покажет `ATO_BRIDGE_TOKEN`),
а на сервере (`./scripts/run.sh`) добавьте счёт с типом «MT5-мост», URL `http(s)://<ip>:8765` и токеном.
Для доступа через интернет — VPN/SSH-туннель или TLS (`-CertFile cert.pem -KeyFile key.pem`).

### Разработка
```bash
cd backend && python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --reload --port 8000
cd frontend && npm install && npm run dev      # http://localhost:5173, /api и /ws проксируются на :8000
```
Документация API: `http://127.0.0.1:8000/api/docs`. Настройки — переменные окружения `ATO_*` (см. `backend/.env.example`).

## Известные ограничения
* Время в данных MT5 (бары, сделки) — время торгового сервера брокера; отображается как есть. Смещение сервера
  определяется по свежим котировкам; если рынок закрыт и котировок нет, дневной лимит считается от полуночи UTC.
* Пакет `MetaTrader5` существует только для Windows x64 — режим `local` работает только на Windows.
* Один мост обслуживает один терминал; для N счетов нужно N терминалов (у каждого своя папка) и N мостов.
* Схема БД создаётся автоматически при старте (`create_all`); для изменения схемы в будущих версиях
  потребуются миграции.
